# Myynd intelligence work log

## Goal · 14 September 2026

Make the attention feed useful: recent personal requests and concrete project actions, understandable cards that open their real source, and durable learning from Done / Not relevant. Keep routine deliveries and subscription updates in the Brief. Ground chat and delegated work in current project memory. Simplify the Automations heading.

## Investigation

- The screenshot is evidence of an unwanted card, not an instruction to update `CLAUDE.md` or replay bot sessions.
- Multiple producers create attention items: the feed, the Brief, and automations. Their admission and feedback rules need to agree.
- Existing feed filtering allows undated and old unread documents. Newly indexed files are described as newly arrived even when their contents are historical.
- The Brief currently removes all bulk/transactional mail, so useful delivery and subscription updates have no appropriate destination.
- Work is divided between feed/feedback, chat/memory/delegation, navigation/UI, and Brief/integration. Each area includes focused regression checks.

## Changes and verification

### Implemented

- Shared source classification uses the source's date (seven-day attention window), distinguishes personal mail from promotions and service updates, and excludes CVs and internal agent artifacts. A newly indexed document no longer acquires a new event date.
- Feed generation requires an exact quote supporting the requested action, a clear task and explanation, and a real document identity. Empty output is valid.
- Durable feedback retains a source snapshot when feed items or tasks are completed, dismissed or deleted, including after source removal/reindexing. Related-request matching is scoped; dismissing one human message does not silence that person's unrelated requests. Undo withdraws the corresponding suppression.
- The Brief has a separate service-updates section and cannot create tasks from deliveries, unsupported project guesses or agent instructions. Real tasks retain their explanatory note.
- Existing cached feed items and untouched Brief suggestions receive the same relevance checks on read. Filtering preserves underlying history and user-adopted tasks.
- Chat includes current projects, goals, task state and direction across provider paths, including conversations with no matching documents. Project extraction requires evidence from the person's own words. Consolidation preserves manually written memory and does not promote guesses into fact.
- Delegation returns its final deliverable without intermediate search chatter, reports truncated work, and treats email as email and other documents as task material.
- Original-source navigation opens web links on the user's device. Missing message identity no longer promises to open an email by opening a generic inbox. Gmail preserves source/account context; Outlook imports the provider's message link.
- Gmail and Outlook now preserve read/sent/bulk metadata used by selection. Outlook's documented `webLink` field is the original-message destination ([Microsoft Graph](https://learn.microsoft.com/en-us/graph/api/message-get?view=graph-rest-1.0)).
- Automation page heading is “Your automations” once. Built-in reply-detection automations use the same feedback and recency rules, exclude answered threads, and filter before candidate limits. Explicit custom automation scopes remain intact.
- Read-only mail connections show “Copy draft and open email” instead of a Send button they cannot fulfil. SMTP sending keeps its existing confirmation flow. Copying/opening does not send or complete a task.
- Save-time checks prevent a late model result from reviving an item dismissed during generation. Manual memory changes during consolidation also win over the in-flight result.

### Scope and practical limits

At the end of the initial implementation stage, these changes were in the source workspace and web production build; the desktop package had not yet been replaced. Those first tests used isolated temporary data and simulated model/mail providers. The subsequent installation and live checks are documented below.

The default attention window is seven days from the source timestamp. Older documents remain searchable when explicitly needed. Project extraction fills new/empty goals from explicit user statements; it preserves existing goals and closed projects, which remain editable in Memory. Model quality still depends on the configured provider and connected source coverage. Repository execution remains tied to the app's existing supported tool and permission flow; a generated draft is not reported as an external action completed. Gmail/Outlook read access alone does not grant in-app sending; the UI hands the prepared draft to the user's email app.
